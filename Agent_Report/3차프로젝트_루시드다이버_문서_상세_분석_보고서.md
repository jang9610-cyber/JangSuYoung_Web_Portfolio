## 0. 결론 요약

《침몽도시: 루시드 다이버》는 단순히 “서브컬처 캐릭터가 등장하는 익스트랙션 게임”이 아니다.

이 프로젝트가 실제로 검증하려 한 질문은 다음 한 문장으로 정리된다.

> **익스트랙션에서 회수한 보상이 캐릭터의 기억과 관계 회복, 그리고 다음 출격 준비로 동시에 이어질 수 있는가?**

프로젝트의 핵심 설계는 두 장르의 충돌을 회피하지 않고 하나의 보상 루프로 묶은 데 있다.

- 익스트랙션은 실패했을 때 세션 성과를 잃어야 긴장감이 생긴다.
- 서브컬처 캐릭터 게임은 캐릭터와의 관계가 계속 유지되어야 애착이 쌓인다.
- 루시드 다이버는 **캐릭터 자체는 잃지 않되, 이번 세션에서 회수하려던 기억과 전리품은 잃을 수 있다**는 구조로 두 감각을 공존시켰다.
- 기억 파편은 단순 재화가 아니라 다이버가 잃어버린 귀환 로그와 자아의 조각이다.
- 탈출 성공 시 기억 파편은 자동으로 소모되어 동조율과 개인 심상 기록으로 바뀐다.
- 일반 회수품은 창고와 장착 슬롯을 거쳐 다음 출격 준비로 이어진다.

장수영의 역할 역시 “팀장”이라는 직함만으로 설명하기 부족하다.

문서와 작업 기록을 종합하면 장수영은 다음 역할을 수행했다.

1. 두 장르의 충돌을 프로젝트의 핵심 검증 질문으로 압축했다.
2. P0, P0.5, 제외 범위를 분리하고 최상위 SSOT를 고정했다.
3. 기능 구현과 리소스 적용을 분리하는 일정 재편을 주도했다.
4. UI, 캐릭터 모션, Live2D, 오디오, PV를 이용해 추상 기획을 구현 전 검토가 가능한 시청각 프로토타입으로 번역했다.
5. 5인 팀의 작업 기록과 산출물을 하나의 인터랙티브 발표 웹으로 통합했다.

따라서 향후 포트폴리오 웹페이지의 중심 메시지는 “게임 전체를 혼자 만들었다”가 되어서는 안 된다.

대신 다음 문장이 가장 정확하고 강하다.

> **충돌하는 두 장르의 핵심 감정을 하나의 플레이 루프로 정리하고, 문서·UI·캐릭터·오디오·웹 프로토타입을 통해 팀이 구현 전에 판단할 수 있는 형태로 만들었다.**

## 2. 문서 체계와 SSOT 운영 분석

### 2.1 현행 문서 우선순위

`00_README_문서_가이드.md`는 개발 범위 판단 시 다음 순서를 명시한다.

1. `00_최종_P0_정의서.md`
2. `01_P0_시스템_명세서.md`
3. `02_P0_개발자_구현명세서.md`
4. 일정표 및 QA
5. 개발 전달용 문서
6. 기획 부록
7. 아카이브

이 구조의 가장 중요한 의미는 **부록의 매력적인 아이디어가 P0 범위를 자동으로 확장할 수 없다는 점**이다.

프롤로그 10단계, 선택지, 선물/호감도, 다이버 모집, 다단계 스킬, 각성 일러스트, 오염 타이머 같은 요소는 부록에 존재하더라도 최상위 정의서에 없으면 P0 구현 대상이 아니다.

### 2.2 문서 관리에서 잘된 점

- 범위 문서와 아이디어 문서를 물리적으로 분리했다.
- 충돌 시 우선순위를 명시했다.
- P0, P0.5, 제외 범위를 별도로 표시했다.
- 개발 전달 문서는 씬, 매니저, 변수, UI, 테스트 단위까지 내려갔다.
- 일정에는 DoD와 기능 동결 조건이 포함됐다.
- QA는 성공, 실패, 저장, 재출격을 시나리오 단위로 정의했다.
- 버전 이력에 날짜, 변경 사항, 작성자가 남아 있다.
- 문서가 실제 구현과 어긋나는지 확인하는 Unity 교차검증 보고서가 별도로 존재한다.

### 2.3 문서 관리에서 드러난 문제

#### 승인 배너의 의미가 일관되지 않다

루트 가이드는 `[!IMPORTANT]` 배너를 AI 초안 또는 검수 전 상태 표시에 사용한다고 설명한다.

그러나 최상위 P0 정의서도 같은 배너를 사용하면서 자신을 최고 우선순위 SSOT로 선언한다. 일정표와 일부 개발 문서 역시 비슷한 배너를 사용한다.

따라서 배너만 보고 문서 상태를 판단할 수 없다.

향후에는 다음 메타데이터가 필요하다.

```yaml
status: approved | draft | deprecated
owner: 장수영
approved_by: CP, PM, TD
effective_date: 2026-06-22
supersedes: ...
```

#### 최상위 폴더 안에도 검수 전 문서가 섞여 있다

`01_P0_시스템_명세서.md`는 상위 SSOT 폴더에 있지만 헤더에는 검수 전 제안서라고 적혀 있다.

즉, 폴더 위치와 문서 상태가 완전히 일치하지 않는다.

#### 작업 티켓 체크박스가 갱신되지 않았다

`P0_기능_티켓_목록.md`의 체크박스는 모두 미완료 상태로 남아 있다.

반면 7월 13일 Unity 교차검증 보고서는 P0 기능 티켓 36건 중 35건 완료, 1건 부분 완료라고 판단한다.

이것은 구현이 없었다는 뜻이 아니라 **기획 티켓 문서가 실행 상태 추적 도구로 유지되지 않았다는 뜻**이다.

포트폴리오에는 “36개 티켓 중 35개 완료”를 그대로 적기보다 다음처럼 시점을 병기해야 한다.

> 2026-07-13 코드 교차검증 기준 P0 35/36 완료 판정

#### 초기 루트 README는 현재 기준이 아니다

루트 README와 초기 문서에는 Unity 6, HDRP/URP 혼용, Spine, Photon PUN2, Steam, 멀티플레이와 1+2+1 팀 구조가 등장한다.

반면 최종 프로젝트 설명과 현재 포트폴리오는 Unity 2022.3.62f3, URP, AnyPortrait, 싱글 플레이 버티컬 슬라이스를 기준으로 한다.

이는 프로젝트가 잘못됐다는 뜻이 아니라 초기 제안이 크게 축소·변경됐음을 보여준다.

포트폴리오에서는 초기 README의 기술 스택을 현재 사실처럼 사용하면 안 된다.

### 2.4 문서 자체가 보여주는 프로젝트 역량

이 저장소의 강점은 문서의 양이 아니다.

더 중요한 점은 다음 흐름이 기록되어 있다는 것이다.

```text
넓은 초기 아이디어
→ 충돌과 과도한 범위 발견
→ P0 질문 확정
→ 기능/비기능 범위 분리
→ 개발 명세와 티켓 변환
→ QA 시나리오 정의
→ 실제 Unity 구현 교차검증
→ 최종 발표와 회고
```

이 흐름은 장수영 포트폴리오에서 “기획서를 많이 작성했다”보다 훨씬 가치가 크다.

**불확실한 기획을 실행 가능한 기준으로 좁히고, 그 기준과 실제 결과의 차이를 추적했다**는 문제 해결 사례이기 때문이다.

최종 포트폴리오용 문장으로는 조금 더 역할과 결과를 압축할 수 있다.

> **침몽도시에서 회수한 기억을 캐릭터의 관계 회복으로 전환하는 서브컬처 익스트랙션 버티컬 슬라이스**

### 3.3 핵심 감정

이 프로젝트의 감정적 중심은 수집이나 성장보다 “기억하는 책임”에 있다.

- 다이버는 반복되는 실패와 강제 각성 과정에서 기억을 잃는다.
- 관제사는 실패 로그와 귀환 신호를 기억하는 유일한 존재다.
- 플레이어는 강한 유닛을 획득하는 사람이 아니라, 사라지는 신호를 붙잡는 사람이다.
- 다이버 모집은 영입이 아니라 구조다.
- 동조율은 호감도가 아니라 귀환 링크의 안정도다.

이를 압축한 슬로건은 다음과 같다.

> **다이버는 잊는다. 관제사는 기록한다.**

이 슬로건은 세계관 문장이면서 동시에 플레이 구조를 설명한다.

### 3.4 장르 충돌과 해결

| 충돌 | 익스트랙션 측 요구 | 서브컬처 측 요구 | 루시드 다이버의 해결 |
|---|---|---|---|
| 실패 | 획득물 유실이 필요 | 캐릭터 관계는 유지돼야 함 | 캐릭터는 유지, 세션 회수품과 기억 파편은 유실 |
| 반복 플레이 | 더 좋은 장비를 얻기 위해 반복 | 캐릭터 반응과 서사를 보기 위해 반복 | 일반 회수품은 다음 출격, 기억 파편은 관계/서사 보상 |
| 캐릭터 획득 | 전투 유닛 확보 | 애착 대상 수집 | 귀환 신호 발견과 구조로 재해석 |
| 성장 | 전투력 수치 상승 | 관계 변화 체감 | 동조율, 심상 기록, 귀환 대사 변화 |

이 구조가 프로젝트의 가장 강력한 기획 포인트다.

## 5. P0 시스템 상세 분석

### 5.1 플레이어

- 이동은 WASD 또는 방향키를 기준으로 한다.
- 대각선 입력은 0.71 보정으로 속도를 정규화한다.
- 마우스 커서 방향을 바라보고 기본 공격한다.
- 기본 공격은 MP를 소비한다.
- MP는 정신력과 무기 에너지 역할을 동시에 수행한다.
- 상호작용 키는 F다.
- 플레이어 HP가 0이 되면 즉시 강제 각성 실패 결과로 전환한다.

### 5.2 적

P0 적은 한 종류이며 단일 HP 구조다.

- 대기
- 감지
- 추적
- 공격
- 피격
- 사망

Dream Barrier와 심상핵을 분리하는 복잡한 전투는 P0에서 제거됐다.

이 결정은 전투의 독창성보다 **타격 → 처치 → 드롭 → 회수 → 정산**이 끊기지 않는 것을 우선한 것이다.

### 5.3 아이템

P0 문서 사이에는 아이템 명칭 변화가 있다.

| 역할 | 초기/개발 구현명세 표현 | 이후 세계관형 명칭 |
|---|---|---|
| MP 회복 | 마나석 | 기묘한 사탕 |
| HP 회복 | 회복약 | 변질된 붕대 |
| 서사 정산 | 기억 파편 | 기억 파편 |

포트폴리오에는 최종 런타임에서 실제 사용된 명칭을 우선하고, 일반 명칭은 보조 설명으로 병기해야 한다.

### 5.4 기억 파편

기억 파편의 규칙은 프로젝트 전체를 묶는 핵심이다.

- 세션 중 획득한다.
- 성공 탈출 시 결과창에서 자동 소모된다.
- 창고에 저장되지 않는다.
- 동조율 상승과 기록 해금에 사용된다.
- 실패 시 전량 유실된다.
- 각성 보존 슬롯에 넣을 수 없다.
- 글로벌 재화로 누적되지 않는다.

이 규칙 덕분에 기억 파편은 “보라색 재화”가 아니라 **이번 세션에서 되찾은 인격의 증거**가 된다.

### 5.5 결과 정산

#### 성공

- 성공 배너
- 플레이 시간
- 회수품 목록
- 기억 파편 자동 소모
- 동조율 변화
- 심상 기록 해금
- 일반 회수품 창고 저장
- 성공 귀환 대사

#### 실패

- 강제 각성 배너
- 세션 획득물 유실
- 동조율 변화 없음
- 기록 해금 없음
- 창고 누적치 변화 없음
- 실패 귀환 대사

### 5.6 데이터

개발 구현명세는 데이터를 세 범주로 분리한다.

| 범주 | 수명 | 예시 |
|---|---|---|
| 세션 임시 | GameScene 종료 시 소멸 | 기억 파편 수, 회복품 수, 플레이 시간, 탈출 결과 |
| 영속 진행 | 저장 파일 | 동조율, 기록 해금, NEW 여부 |
| 영속 보관 | 저장 파일 | 창고 수량, 장착 슬롯 |

이 분리는 성공/실패 정산을 구현하기 위한 최소한의 데이터 수명 모델이다.

### 5.7 UI

핵심 UI는 다음 여섯 화면이다.

1. 로비/관제실
2. 출격 준비
3. 인게임 HUD
4. 결과창
5. 다이버/기록
6. 창고/인벤토리

UI는 단순 메뉴 묶음이 아니라 보상 순환을 보여주는 구조다.

- 로비는 관계 상태를 보여준다.
- 출격 준비는 이전 성공이 다음 플레이에 미치는 영향을 보여준다.
- HUD는 생존, 시간, 자원, 위험을 동시에 보여준다.
- 결과창은 세션 성과가 관계와 자원으로 변환되는 순간을 보여준다.
- 기록 화면은 감정적 보상을 제공한다.
- 창고는 기능적 보상을 제공한다.

## 6. P0.5 확장 분석

P0.5는 P0의 핵심 루프 위에 위험 판단, 전투 선택, 파밍 다양성, 레벨 밀도를 추가한 단계다.

### 6.1 플레이어 확장

#### 세션 시간 제한

- 기본 세션 시간이 감소한다.
- 0이 되면 강제 각성한다.
- 특정 구역에서 시간 감소 속도가 가속될 수 있다.
- 장비로 시간 감소 속도를 완화할 수 있다.
- 소비 아이템으로 남은 시간을 회복할 수 있다.

#### 시야 제한

- 플레이어와 마우스 방향을 중심으로 부채꼴 시야를 구성한다.
- 적과 상호작용 오브젝트는 시야 범위 안에서만 렌더링한다는 기획이다.
- 구현 교차검증에서는 `VisionGizmo` 존재까지만 확인됐고 실제 마스킹 구현은 부분 확인 상태였다.

#### 달리기

- 달리기는 MP를 지속 소비한다.
- MP가 임계치 아래로 떨어지면 일정 시간 달릴 수 없다.
- MP가 공격과 달리기의 공통 자원이므로 이동과 화력 사이의 선택이 생긴다.

#### 구르기

- 방향 회피
- MP 소비
- 쿨타임
- 동작 중 무적

7월 10~13일 QA에서는 구르기 벽 관통이 치명 이슈로 보고됐다.

#### 탈출 채널링

- P0의 즉시 탈출을 3초 채널링으로 확장했다.
- 피격 시 탈출이 취소된다.
- 전화부스가 안전 버튼이 아니라 마지막 위험 판단 지점이 된다.

#### 각성 보존 슬롯

- 실패해도 슬롯 안 아이템은 보존된다.
- 기본 4칸으로 설계됐다.
- P0의 “전량 유실”보다 완화된 구조다.

### 6.2 스킬

P0.5 스킬 시스템은 단순 버튼 명세가 아니라 다음 요소까지 정의한다.

- 사용 가능 상태
- MP 비용
- 쿨타임
- 시전 중 이동 제한
- 타겟 방식
- 사거리
- 범위 형태
- 효과 대상
- 효과 지연
- VFX/SFX
- 다중 효과

대표 예시는 프리즘 유탄이다.

- MP 20
- 쿨타임 5초
- 사거리 15m
- 0.5초 후 반경 3m, 공격력 150% 피해
- 반경 18m 적을 2.5초간 유인하는 디코이 동시 생성

이 스킬은 피해와 AI 유인을 결합해 전투와 잠입/유도 플레이를 동시에 보여준다.

### 6.3 아티팩트

아티팩트는 세션 중 획득하고 즉시 장착하는 특수 장비다.

| 등급 | 아이템 | 핵심 효과 |
|---|---|---|
| Normal | 굳어버린 구급 봉투 | HP 초당 +2 |
| Uncommon | 역류하는 자양강장제 | MP 초당 +5 |
| Rare | 마모되지 않는 카트 바퀴 | 이동 속도 +30% |
| Epic | 지연된 시계 태엽 | 시간 감소 속도 ×0.6 |
| Legend | 침식된 보안 경광봉 | 공격 속도 증가, 공격 MP 소비 감소 |

일반 지역과 고위험 창고는 등급 드롭 확률이 다르다.

이 구조는 레벨의 위험도와 파밍 가치를 연결한다.

### 6.4 소비 기물

| 아이템 | 효과 | 채널링 | 쿨타임 |
|---|---|---:|---:|
| 변질된 붕대 | HP +40 | 1.5초, 피격 취소 | 20초 |
| 기묘한 사탕 | MP +50 | 즉시 | 15초 |
| 침몽의 모래시계 | 세션 시간 +90초 | 2초, 피격 취소 | 없음 |

아이템마다 “언제 안전하게 사용할 수 있는가”가 다르며, 세션 시간 자체도 회복 가능한 자원으로 취급한다.

### 6.5 꿈식자 AI

P0.5의 적은 단순 추적형에서 모듈형 FSM으로 확장됐다.

대표 상태는 다음과 같다.

```text
Idle / Patrol
→ Suspicious
→ Investigate
→ AlertCry
→ Chase
→ Intercept
→ Attack 1 / Attack 2
→ Search
→ Return
→ Berserk
→ Dead
```

핵심 설계 원칙은 다음과 같다.

- 시야 거리, 시야각, 장애물 가림이 모두 맞아야 직접 감지한다.
- 소리는 즉시 추격이 아니라 의심과 조사로 이어진다.
- 플레이어가 빠르게 이동할 때 짧은 미래 위치를 예측해 차단 이동한다.
- 예지처럼 보이지 않도록 예측 거리와 갱신 주기를 제한한다.
- 공격은 2단 전진 공격이며 전조와 실제 판정이 일치해야 한다.
- HP 50% 이하에서 개체별 1회 광폭화한다.

#### 루시드 낙인

- 피격 시 세션 시간이 5초 감소한다.
- 최대 2중첩이다.
- 2중첩 시 주변 적에게 플레이어 위치가 내부적으로 공유된다.
- 플레이어에게는 직접 표시되지 않는 적 내부 감각 신호다.
- 이동 속도 감소나 긴 경직 대신 시간 손실과 추적 압박을 준다.

이 시스템은 적의 피해가 HP 감소에만 머물지 않고 **탈출 가능 시간과 은폐 상태를 동시에 훼손**하도록 만든다.

### 6.6 레벨: 슈퍼숍

P0.5 레벨은 약 40m × 40m의 대형 마트다.

#### 3중 레이어

1. 외곽 야외 도로
2. 마트 초입과 로비
3. 중앙 매장과 북쪽 물류 창고

플레이어는 외곽에서 시작해 중앙의 고위험·고보상 구역으로 들어갔다가 외곽 전화부스로 되돌아온다.

## 7. 세계관과 서사 분석

### 7.1 침몽도시

침몽도시는 현실과 꿈이 겹쳐진 재난 구역이다.

- 반복되는 실패와 귀환이 잔류한다.
- 현실 무기는 제대로 작동하지 않는다.
- 다이버는 꿈속 무장인 드림 포지드를 사용한다.
- 실패와 강제 각성이 반복되면 기억과 자아가 손상된다.
- 남겨진 경험과 감정은 기억 파편과 잔류 로그가 된다.
- 완전히 구조받지 못한 다이버는 괴이로 변질될 수 있다.

### 7.2 관제사

관제사는 선의로 구조하는 추상적 영웅이 아니다.

- 귀환 신호를 읽을 수 있다.
- 다이버가 잊은 실패를 기록으로 보유한다.
- 링크를 유지하지 않으면 다이버가 사라지는 것을 안다.
- 사라지는 순간의 로그를 가진 유일한 사람이다.

이 설정은 플레이어가 왜 반복 출격을 지시하고 캐릭터를 구해야 하는지 설명한다.

### 7.3 다이버

다이버는 수집 대상이나 전투 유닛으로만 정의되지 않는다.

- 침몽도시의 왜곡을 버틸 수 있는 생존자
- 꿈속 무장을 사용할 수 있는 특수 요원
- 동시에 기억과 자아를 잃을 위험이 큰 사람
- 구원 후에도 자신과 같은 신호를 감지해 다시 들어가는 구조자

### 7.4 채린

채린은 P0의 메인 다이버이자 “구원 가능성을 처음 증명한 불완전 귀환자”다.

핵심 성격은 방어적 불신이다.

- 관제사와 기관을 쉽게 믿지 않는다.
- 관제사의 목소리에서 이유를 알 수 없는 기시감을 느낀다.
- 동조율이 오르면서 목소리를 노이즈가 아닌 귀환 신호로 받아들이기 시작한다.
- 깨진 안경 렌즈와 프리즘은 캐릭터와 기억 파편의 시각 모티프다.

### 7.5 동조율

동조율은 호감도가 아니다.

정확한 정의는 **관제사와 다이버 사이의 귀환 링크 안정도**다.

이 정의 덕분에 관계 성장과 게임 시스템이 같은 용어를 공유한다.

- 낮을 때: 관제사 목소리가 노이즈처럼 들린다.
- 상승 중: 설명할 수 없는 기시감이 생긴다.
- 일정 단계: 잃어버린 기억과 심상 기록이 복구된다.

### 7.6 개인 심상 기록

개인 심상 기록은 텍스트 보상이지만 단순 도감이 아니다.

- 세션 플레이 결과로 해금된다.
- 캐릭터의 실패와 귀환을 기록한다.
- 관제사만 알고 있던 과거가 캐릭터에게 다시 돌아오는 순간을 만든다.
- 플레이어의 전투 성과를 감정적 보상으로 전환한다.

P0의 기록 01은 “끊어진 귀환 로그”를 중심으로 한다.

### 7.7 서사의 강점

- 메타 진행을 세계관 안에서 설명한다.
- 캐릭터 수집을 구조로 재해석한다.
- 실패 유실을 감정적 손실과 연결한다.
- 반복 플레이의 이유를 “더 강한 장비”와 “더 많은 기억”으로 이중화한다.
- UI의 동조율, 기록, 로그, 관제실이 모두 같은 세계관 언어를 사용한다.

### 7.8 서사의 위험

- 초기 문서의 채린과 최종 발표의 유안이 혼재한다.
- P0 제안서에서는 채린이 주인공이지만 최종 런타임 및 발표 자료에는 유안이 중심이다.
- 초기 “관제사와 채린” 서사와 이후 “관제사와 유안” 서사의 변경 이유가 한 문서에 완전히 정리돼 있지 않다.
- 다이버 구원, 모집, 괴이 변질은 장기 설정이며 실제 빌드에서 모두 구현된 것은 아니다.

웹페이지는 캐릭터 이름과 시점에 대해 최종 확정이 필요하다.

현재 런타임 증거와 최종 발표 자료만 보면 유안을 메인으로 사용하되, P0 기획 단계의 채린은 “초기 검증 캐릭터” 또는 기획 변경 과정으로 분리하는 편이 안전하다.

- 신규 기능 금지 시점을 명시했다.

- 일정표는 v0.3 초안 상태이며 최종 실적표로 갱신되지 않았다.

- “기획 동결” 이후에도 P1, 서사 개편, 발표 웹, UI 개선이 계속 추가됐다.

포트폴리오에서는 일정표 원문보다 **범위를 줄인 결정, 다시 확장한 조건, 최종 안정화 과정**을 중심으로 보여주는 것이 좋다.

## 11. 결과물의 강점

### 11.1 기획 강점

- 장르 결합이 분위기 수준에 머물지 않는다.
- 기억 파편의 정산 규칙이 서사와 시스템을 동시에 수행한다.
- 실패의 손실과 캐릭터 관계의 연속성을 양립시킨다.
- 캐릭터 수집을 구조 행위로 재정의한다.
- P0 질문과 성공 조건이 명확하다.

### 11.2 제작 강점

- 기획, 개발 전달, QA까지 이어지는 문서 사슬이 있다.
- 런타임 캡처와 코드 교차검증이 있다.
- UI Before/After가 존재한다.
- 캐릭터, 오디오, 영상, 웹까지 통합된 증거가 있다.
- 팀의 문제 해결 과정이 일지로 남아 있다.

### 11.3 포트폴리오 강점

- “아이디어를 냈다”가 아니라 “범위를 줄이고 구현 가능한 형태로 만들었다”를 증명할 수 있다.
- 초기 목업과 최종 결과를 비교할 수 있다.
- 기획과 실제 화면의 연결을 보여줄 수 있다.
- 기술적 트러블슈팅을 개인 경험으로 설명할 수 있다.
- 프로젝트 관리, 콘텐츠 프로토타이핑, 웹 커뮤니케이션 역량을 한 사례에서 보여줄 수 있다.

따라서 이 페이지는 새 페이지의 **콘텐츠·이미지·상호작용 원천**으로 사용하되 정보 구조는 다시 편집해야 한다.

이 목업은 “화면을 예쁘게 그렸다”보다 더 중요한 증거다.

- 상태별 화면을 연결했다.

다만 이 목업에는 P0에서 제외됐던 그리드형 인벤토리 또는 확장 사양이 포함된다. 새 웹에서는 반드시 P0.5/프로토타입 UI라는 라벨을 붙여야 한다.

- 정적인 PPT보다 기획과 구현의 비교가 쉽다.
- 팀원별 대표 사례를 하나의 경험으로 묶는다.
- 미디어 오류와 장면 진입 상태를 고려한 JavaScript가 있다.
- 발표 웹 자체가 장수영의 웹 프로토타이핑 역량을 보여준다.

### 13.9 기존 웹들을 그대로 재사용하기 어려운 이유

- 33개 활성 Scene은 일반 방문자에게 너무 길다.
- 팀 전체 발표가 중심이라 장수영의 역할이 중간에 분산된다.
- 발표자 발화가 없으면 일부 화면의 의미가 약해진다.
- 강한 전환 중심 구조는 스크롤 탐색과 검색 접근성이 낮다.
- 기능과 수치가 여러 시점의 문서를 함께 반영한다.
- 일부 장면은 Q&A와 팀 인계용이다.
- 스타일과 스크립트가 매우 크고 유지보수 비용이 높다.
- 장문 소개 페이지와 발표 페이지 사이에 중복 콘텐츠가 많다.
- UI 목업은 P0와 P0.5 범위를 혼합하므로 라벨 없이 노출하면 구현 범위를 오해할 수 있다.

따라서 기존 웹은 소스와 미디어를 재사용하되, 새 페이지는 독립적인 사례 연구 구조로 다시 설계해야 한다.

## 14. 3차 프로젝트 포트폴리오 웹페이지 제안

### 14.1 페이지 목표

방문자가 3~5분 안에 다음을 이해해야 한다.

1. 어떤 게임인가
2. 무엇이 독특한가
3. 장수영은 어떤 문제를 해결했는가
4. 기획이 실제 결과로 어떻게 이어졌는가
5. 어떤 기술과 제작 역량을 사용했는가
6. 직접 플레이하거나 더 자세한 자료를 어디서 볼 수 있는가

### 14.2 핵심 메시지

#### 메인

> **캐릭터 애착과 익스트랙션의 손실을 기억 회수 루프로 연결한 7주 팀 프로젝트**

#### 개인 역할

> **P0 범위와 핵심 보상 루프를 정의하고, UI·캐릭터·오디오·웹 프로토타입으로 구현 전 판단 기준을 만들었다.**

### 14.3 권장 페이지 구조

#### 1. Hero

- 게임 로고
- 침몽도시 키비주얼
- 유안 또는 최종 확정 캐릭터
- 장르, 기간, 인원, 역할
- 플레이 영상
- 빌드 다운로드
- GitHub 문서

#### 2. Design Challenge

화면을 좌우로 나눠 보여준다.

- 왼쪽: 관계가 지속돼야 하는 서브컬처
- 오른쪽: 실패 시 잃어야 하는 익스트랙션
- 중앙: 기억 파편

방문자가 중앙 파편을 클릭하거나 드래그하면 해결 구조가 나타난다.

#### 3. Dual Reward Loop

기억 파편과 일반 회수품을 두 갈래로 보여준다.

```text
기억 파편 → 동조율 → 심상 기록 → 대사 변화
일반 회수품 → 창고 → 장착 → 다음 출격
```

이 섹션은 이 프로젝트의 가장 중요한 인터랙션이 되어야 한다.

#### 4. P0 Decision

- 초기 아이디어
- 제거한 기능
- 남긴 핵심 루프
- 성공 기준

P0/P0.5/제외 항목을 필터 가능한 카드로 보여주면 좋다.

#### 5. Playable Loop

기존 런타임 이미지 5종을 재사용한다.

1. 세션 진입
2. 루팅
3. 전투
4. 전화부스 탈출
5. 성공/실패 결과

자동 슬라이드보다 클릭 가능한 단계형 갤러리가 적합하다.

#### 6. UI From Plan to Runtime

기존 `CP_UI_BeforeAfter.png`와 원본 두 이미지를 이용한 드래그 비교.

- 와이어프레임
- 실제 로비
- 어떤 정보 구조가 유지됐는지
- 무엇이 구현 과정에서 바뀌었는지

#### 7. Character Pipeline

- 원화 파츠
- AnyPortrait 메시/Bone
- 방향별 동작
- URP 셰이더
- Live2D
- 런타임

작업 툴 나열보다 입력→처리→결과 흐름으로 보여준다.

#### 8. Audio Pipeline

- 상황별 사운드 요구
- 소스 확보
- FL Studio 후가공
- 58종 분류

- 인게임 출력

가능하면 3~4개의 짧은 소리를 직접 비교 재생한다.

#### 9. Troubleshooting

최대 3건만 깊게 보여준다.

추천 사례:

1. AnyPortrait 투명 셰이더와 URP 그림자
2. Canvas 재활성화 후 Live2D 영상 정지
3. 발표 웹 미디어 첫 진입/레이아웃 문제

각 사례는 다음 형식이 좋다.

```text
현상 → 원인 → 수정 → 검증
```

#### 10. Team and Ownership

5인 팀 역할을 짧게 보여주고 장수영의 정확한 소유 범위를 강조한다.

### 14.4 비주얼 방향

기존 프로젝트의 시각 언어를 살린다.

- 검정과 짙은 남보라
- 오팔/프리즘

다만 발표 웹처럼 모든 섹션을 풀스크린 Scene으로 만들 필요는 없다.

현재 포트폴리오의 탐색 방식에 맞춰 긴 스크롤형 사례 연구로 만들고, 핵심 구간에만 인터랙션을 둔다.

### 14.5 반응형 원칙

- 모바일에서도 본문과 CTA가 먼저 보이게 한다.
- 풀스크린 고정 높이에 의존하지 않는다.
- 영상에는 포스터와 수동 재생을 제공한다.

- 모션 감소 설정을 지원한다.
- 대용량 GIF는 MP4/WebM으로 전환한다.
- 원본 이미지의 비율을 유지한다.

### 14.6 성능 원칙

기존 저장소 미디어는 매우 크다.

- Above-the-fold 영상 1개만 우선 로드
- 이미지 AVIF/WebP 변환
- `srcset` 제공
- 영상 `preload="metadata"` 또는 `none`
- 화면 밖 미디어 지연 로드
- GIF 대신 반복 MP4/WebM
- 발표용 고해상도 원본과 웹용 파생본 분리

### 14.7 접근성

- 모든 인터랙션을 키보드로 조작 가능하게 한다.
- 이미지마다 의미 있는 대체 텍스트를 제공한다.
- 색만으로 성공/실패를 구분하지 않는다.
- 영상 자막 또는 텍스트 요약을 제공한다.
- 자동 재생 음소거를 기본으로 한다.
- 포커스 스타일을 유지한다.
- 터치 영역 최소 크기를 확보한다.

## 18. 최종 평가

이 프로젝트의 가장 큰 자산은 기능 수가 아니다.

가장 가치 있는 것은 다음 세 가지다.

### 1. 장르 문제를 시스템 문제로 바꾼 점

“서브컬처와 익스트랙션을 섞었다”에서 멈추지 않고, 실패 유실과 관계 지속의 충돌을 기억 파편 정산 구조로 해결했다.

### 2. 범위를 실제 제작 단위로 줄인 점

넓은 초기 기획을 캐릭터 1명, 세션 1개, 적 1종, 기록 1개로 줄이고 성공 조건을 정의했다.

### 3. 기획을 여러 매체로 번역한 점

문서, UI, 캐릭터, 사운드, 영상, 웹을 이용해 구현 결과를 미리 검토하고 최종 결과를 설명했다.

따라서 3차 프로젝트 페이지는 “완성된 게임의 기능 소개”만 해서는 부족하다.

이 프로젝트가 포트폴리오에서 증명해야 할 핵심은 다음이다.

> **장수영은 아이디어를 제시하는 데서 끝나지 않고, 충돌을 발견하고 범위를 결정하고, 팀이 구현할 수 있는 규칙과 시청각 증거로 바꾸며, 마지막에는 그 과정을 하나의 인터랙티브 서사로 설명할 수 있다.**
